Stage 1 deep-dive: modeling/graph_analytics.py loads tenant data, runs five independent graph detectors, saves evidence-rich findings, and replaces the current UserGraphFlags snapshot.

Stage 1 — modeling/graph_analytics.py
Startup (once per run)
1
Connect & Sync Graph Tables
DELETE + INSERT into NomGraph_Person and NomGraph_Nominated from live Users / Nominations. Full reload every run (tables are small).
2
Evict Stale Embeddings
DELETE from NomGraph_NominationEmbedding where nomination is outside the detection window (default 180 days) or no longer Approved/Paid. Keeps the cache table bounded.
↓ for each tenant
Data Load (per tenant)
3
Load nominations
Status IN ('Approved','Paid'), within rolling window. Only committed spend.
4
Load users + ever-active set
All users (for desert detection, no date filter) + union of all-time nominator/beneficiary IDs.
5
Load existing FindingHashes
SHA-256 fingerprints already in GraphPatternFindings — used to dedup before insert.
↓
5 Pattern Detectors (run in series → detected_findings list)
① Ring
networkx simple_cycles, size 3–8. frozenset dedup. Severity by $ amount.
② SuperNominator
Out-degree > mean+2σ AND >3× median AND ≥5 sent.
③ CopyPaste
Embedding cosine ≥0.92, cluster ≥3.
→ Check embedding cache (DB)
→ Encode delta only (MiniLM-L6-v2)
→ Save new vectors to cache
→ Chunked union-find (no full N×N)
④ HiddenCandidate
User name appears ≥5× in description text but never as BeneficiaryId. Active users only.
⑤ Desert
Whole team (≥3 members) absent from both sides of all-time nominations.
All 5 detectors append to a single detected_findings list (pre-dedup). Each finding carries a deterministic SHA-256 fingerprint (TenantId + PatternType + sorted users + sorted nomination IDs).
↓
Persist Findings
6
Dedup & Insert → GraphPatternFindings
Two-pass dedup: (a) skip hashes already in DB, (b) skip intra-run duplicates. DB unique index on (TenantId, FindingHash) is the safety net. Only net-new rows inserted.
↓
Current Graph Flag Snapshot (per tenant)
7
Replace → UserGraphFlags
Aggregate per user from findings: IsInRing, RingMaxUserCount, RingMaxNominationCount, IsSuperNominator, IsInCopyPasteCluster, CopyPasteClusterSize, HighestSeverity, and FindingsJson. Same-day reruns fully replace the snapshot.
Graph output is consumed only by the independent Graph decision engine. RF training and inference do not read this snapshot.
↓ free tenant memory → next tenant
Inputs
dbo.Users dbo.Nominations dbo.Tenants
Filtered to Approved/Paid within window_days (default 180).
Graph Tables (refreshed each run)
dbo.NomGraph_Person dbo.NomGraph_Nominated
Full DELETE+INSERT. Small tables, SQL Server graph-edge format.
Embedding Cache
dbo.NomGraph_NominationEmbedding
VARBINARY float32 vectors. Stale rows evicted at startup. ~96% cache hit rate at steady state → only 1 week of new descriptions encoded per run.
Findings Output
dbo.GraphPatternFindings
Append-only audit log. FindingHash unique index prevents duplicates. PatternType / Severity / AffectedUsers (JSON) / NominationIds (JSON) / TotalAmount.
Independent Graph Snapshot Output
dbo.UserGraphFlags
Includes complete FindingsJson evidence for affected users. The integrity worker reads the current successful snapshot; RF does not.
